How MeterX measures

One person built MeterX to answer a plain question honestly: is the connection I pay for the connection I get?

The test

A full test takes about twenty seconds. It first measures ping and jitter with a run of small requests. It then downloads with four parallel streams for a fixed time and uploads with three, so one slow stream cannot hide a fast line. The first moments of each phase, while the connection speeds up, and the last moments are left out, so the figure is the steady rate.

Latency under load

While the line is full, MeterX keeps pinging. The difference between the ping at rest and the ping under load is bufferbloat, the reason a call stutters when someone else starts a download. It is graded from A, almost no rise, to F, a rise of several hundred milliseconds.

Where it tests

By default MeterX tests against a small Cloudflare Worker, so every test goes to the nearest of Cloudflare's locations. The worker sends and receives test bytes and keeps nothing. You can also run the self-hosted server from the repository on your own machine or network and point the extension at it.

What it keeps

Up to 200 results, in your browser's own storage. Nothing is sent anywhere else, and there is no account. You can export them as a PDF report, CSV or JSON at any time.

Open source

The extension, the worker and the self-hosted server are open source under AGPL-3.0 at github.com/ajithakdev/meterx. Bug reports and ideas go in the issues there.
