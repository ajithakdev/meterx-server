## Commands

npm workspaces monorepo (`packages/*`). Run from the root unless noted.

```bash
npm install
npm run build          # all workspaces: extension -> packages/extension/dist, server -> packages/server/dist/server.js
npm test               # vitest in extension + server (worker and shared have no tests)
npm run lint           # eslint (TS, CSS, Markdown)
npm start              # self-host Express server on :3000 (needs a prior build)

# Single test file / test name
cd packages/server && npx vitest run src/app.test.ts
cd packages/extension && npx vitest run src/quality.test.ts -t "excellent"

# Type check (CI does this for server and extension only)
cd packages/server && npx tsc --noEmit
cd packages/extension && npx tsc --noEmit

# Worker
cd packages/worker && npx wrangler dev      # local
cd packages/worker && npx wrangler deploy   # deploy to Cloudflare (free plan only)
```

Load the extension unpacked from `packages/extension/dist/` (rebuild after every change; `static/` is copied verbatim into `dist/`).

CI (`.github/workflows/ci.yml`) runs lint, both type checks, build and tests on Node 22, and on pushes to `main` uploads `meterx-extension.zip`.

## Architecture

Three runtimes share one contract:

- **`packages/extension`**: Manifest V3 extension, bundled by `build.mjs` (esbuild, ESM, 4 entry points: `background`, `popup`, `options`, `sidepanel`). All measurement logic lives in `src/background.ts` (service worker). The UI pages are thin: they send `chrome.runtime` messages (`startTest`, `cancelTest`, `getServerUrl`, `setServerUrl`, `rescheduleTests`, `openSidePanel`) and listen for `testProgress` / `testComplete` / `testError` broadcasts. Helpers (`quality`, `history`, `isp`, `share`, `chart`, `sparkline`, `export-*`) are imported by the pages.
- **`packages/worker`**: Cloudflare Worker, the default backend (`DEFAULT_SERVER_URL` in `background.ts` and `DEFAULT_URL` in `options.ts`, plus `host_permissions` in `static/manifest.json`; change all three together). Streams generated bytes, no storage.
- **`packages/server`**: Express 5 self-host fallback. `app.ts` exports the app (tested with supertest in `app.test.ts`); `server.ts` only listens. Generates zero-filled `test-files/*.bin` on demand. CORS allows extension origins plus `CORS_ORIGINS` (comma list). `src/test.ts` is a legacy CommonJS smoke script, not part of `npm test`.
- **`packages/shared`**: types and thresholds only (`QUALITY_THRESHOLDS`, `USE_CASE_REQUIREMENTS`, `TestResults`, `HistoryEntry`, ...), consumed as raw TS (`main: ./src/index.ts`) and bundled into each package.

**Server API contract** (worker and Express must stay in sync): `GET/HEAD /ping`, `GET /test-file/{1|5|10|25}MB.bin`, `POST /upload` (`application/octet-stream`, body discarded), `GET /health`, `GET /ip`. Allowed sizes are duplicated in `worker/src/index.ts` (`ALLOWED_SIZES`) and `server/src/app.ts` (`ALLOWED_FILE_SIZES`); the extension always downloads the 25 MB file. Responses must send `Timing-Allow-Origin` so the extension can read DNS timing.

**Measurement** (`background.ts`): parallel streams (4 download, 3 upload) for a fixed duration (`MEASURE_DURATION_MS`), with ramp-up and tail trimmed from the throughput samples, plus loaded-latency pings during load for bufferbloat. The server rate limits in `app.ts` are sized for this burst pattern; raise them if you add streams.

**Storage**: `chrome.storage.sync` holds settings (`serverUrl`, `ispPlan`, `scheduleMinutes`, `notifyOnDrop`); `chrome.storage.local` holds `history` (capped at `MAX_HISTORY` = 200). Scheduled tests use `chrome.alarms` and are re-registered on install/startup.

Custom server URLs need a runtime host-permission grant (`optional_host_permissions`); the options page requests it.

## Gotchas

- Version strings are hard-coded in several places (root and package `package.json`s, file headers, `export-data.ts`, `/health` in `app.ts` and its assertion in `app.test.ts`). `manifest.json` uses its own Chrome-compatible version. Grep for the old version when bumping.
- `manifest.json` description must stay within the store's 132-character limit.
- `.junie/guidelines.md` describes the old pre-monorepo JS layout and a Render URL; it is stale, trust the code.
